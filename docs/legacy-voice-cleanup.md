# 旧音声処理の整理と復元

Live移行後に使われなくなった、旧ASR・TTS・独自Fillerの状態管理を削除した。
ElevenLabsのASR/TTSクライアント、Filler Generator本体、Puppeteer実装と依存関係は、
先の移行コミット `07d507c` で削除済み。本変更は残っていた実行時の互換処理を対象にする。

## 削除したもの

- `StateStore`の旧ASR途中認識、セグメント管理、発話中フラグ。
- 旧TTS・Fillerのイベント処理、再生状態、公開用の状態整形。
- カーネル起動時に旧TTS・Fillerの未完了再生を中断扱いにする復旧処理。
- ダッシュボード向けスナップショットの旧ASR部分の加工。
- 上記に依存する旧TTSの復旧テストと、現行READMEの古い説明。

行動状態APIなどの`state.output.tts`、`state.output.filler`、
`state.interaction.asr_partial`、`state.interaction.user_speaking`は出力しなくなる。
Liveの音声と文字起こしは、引き続きLive接続管理とブラウザ側で扱う。

## ログと現行機能

旧音声イベントが保存済みの`observations.jsonl`に残っていても読み込みは継続する。
旧イベントの専用状態を作らず、元のログを削除・変換しない。
機体操作のintention/outcomeと再起動時の未完了操作の復旧処理は引き続き使う。
Liveの会話・記憶処理、センサー、カメラ、BEATs咳検出は変更しない。

`archives/`の過去の設計資料と、声の比較用プロンプトは参照資料として残す。
実行時には読み込まれない。現在の実行コードと混同しないよう、アーカイブの索引を参照する。

## 復元

整理前の全体は `4dcae35`（PR #24マージ後のmain）に残る。
旧Puppeteer・ElevenLabs方式の全体は `78127af` に残る。

削除を取り消す場合は、この整理コミットを`git revert`して別PRにする。
特定ファイルだけ必要なら、対象コミットから`git restore --source=<commit> -- <path>`で復元できる。
旧方式を実際に動かすには、その当時の依存関係や設定も合わせて復元する必要がある。
ソースコードの復元では、実行時データや外部サービス側の状態は巻き戻らない。

## 検証

旧ASR・TTS・Fillerの記録と現行の入力・環境観測・操作結果を混ぜてリプレイし、
現行状態が復元されること、旧音声状態が公開されないこと、原本が書き換わらないことを検証する。
`node --test`で全99件が成功。旧イベントのリプレイのほか、Live接続、記憶処理、
機体操作の監査・復旧、BEATsの回帰テストを含む。外部の有料APIは使っていない。
